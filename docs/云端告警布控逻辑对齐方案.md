# 云端告警与布控逻辑对齐修改方案

> 基准：边缘设备端 `edge_ai_video_analyzer/Admin` 最新代码
> 目标：云端 `1.cloud_eai_server/admin` 的告警管理与布控管理在**功能、字段、状态机、校验逻辑**上与边缘端保持一致
> 范围：数据库模型、视图接口、URL 路由、前端页面，全链路对齐

---

## 一、两端现状对比总览

### 1.1 告警模块

| 维度 | 边缘端（基准） | 云端（现状） | 差距 |
| --- | --- | --- | --- |
| 页面拆分 | 4 个独立页面：事件/车牌/人脸/计数 | 单页 `alarm/index.html` | 需拆分 |
| 状态机 | 0未读/1未处理/2已处理/3误报/**4待复检/5复检超时/6复检为误报** | 0未处理/1已处理/2误报 | 需扩展 |
| 关键字段 | `risk_level`、`detect_objs`、`task_name`、`deal_info` | 无 `risk_level`/`detect_objs`/`deal_info` | 需补字段 |
| 车牌/人脸特有 | `main_plate_*`、`main_track_*` 系列字段 | 已有但展示逻辑不同 | 需对齐展示 |
| 计数告警 | 独立页面 + 历史记录 + 清零策略 | 无 | 需新增 |
| 数据表 | `av_alarm` + `av_statistic_alarm` | `eai_node_alarm` 单表 | 需拆表/补表 |

### 1.2 布控模块

| 维度 | 边缘端（基准） | 云端（现状） | 差距 |
| --- | --- | --- | --- |
| 算法分类 | `base/carplate_task/face_task/action_task/car_task/object_task/vla_task/other_task` | 无分类，透传节点 | 需补分类展示 |

| 配置校验 | `validate_counting_config()` 本地校验 | 无校验，直接转发节点 | 需补校验 |

| 辅助接口 | `api_get_counting_config` / `api_validate_counting_config` / `api_format_counting_info` | 无 | 需新增 |

## 五、数据同步逻辑（云端 ↔ 边缘节点）

### 5.1 告警同步

边缘端新增告警字段后，云端接收报警推送的接口需同步更新：

- 文件：`app/utils/AlarmUtils.py`（或 `InnerlView.py` 中报警接收逻辑）
- 修改点：
  - 接收 `risk_level`、`detect_objs`、`deal_info` 并落库
  - 接收计数类告警时，同时写入 `eai_node_statistic_alarm`
  - `state` 按新语义映射存储

### 5.2 布控下发

云端 `api_openAdd` / `api_openEdit` 转发节点前：
1. 若算法类型为 `cross_line_counting`，先执行 `validate_counting_config`
2. 校验失败直接返回错误，不转发节点
3. 校验通过则原样转发（节点端有自己的校验，云端只做前置拦截）

### 5.3 边缘端 open 接口补充（重要）

经核查，边缘端现有 open 接口**缺少布控新增/编辑接口**，云端调用已失效。需同步修改：

| 边缘端接口 | 现状 | 修改内容 |
| --- | --- | --- |
| `control/openAdd` | **不存在** | **新增**：接收布控配置（含计数策略JSON），本地 `validate_counting_config` 校验后保存并启动布控 |
| `control/openEdit` | **不存在** | **新增**：接收布控更新（含计数策略JSON），校验后更新并重启布控 |
| `control/openIndex` | 存在 | 扩展返回字段：增加 `algorithm_type`（分类）、`counting_config_summary`（计数配置摘要文本） |
| `control/openStartControl` | 存在 | 启动前校验计数配置有效性（若算法为 `cross_line_counting`） |
| `control/openStopControl` | 存在 | 保持不变 |
| `control/openDel` | 存在 | 删除布控时，同步清理 `av_statistic_alarm` 中关联的计数统计数据 |

def migrate_alarm_state(apps, schema_editor):
    NodeAlarm = apps.get_model('app', 'NodeAlarmModel')
    # 旧 0->1, 1->2, 2->3
    NodeAlarm.objects.filter(state=0).update(state=1)
    NodeAlarm.objects.filter(state=1).update(state=2)

## 八、注意事项

1. **云端多节点维度**：所有查询/展示必须带 `node_code` 过滤，边缘端单设备无此问题，云端需额外处理。
2. **state 语义迁移**：旧数据必须先迁移再上线新代码，避免状态混乱。
3. **计数清零**：边缘端 `api_counting_manual_reset` 是本地操作；云端需同步转发到对应节点，同时更新云端 `eai_node_statistic_alarm`。
4. **车牌/人脸字段**：云端已有 `main_plate_*` 字段，展示逻辑按边缘端页面补齐即可，无需改表。
5. **回滚方案**：Migration 提供反向操作（`reverse_code`），state 迁移前建议备份 `eai_node_alarm` 表。
