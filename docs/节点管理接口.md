# 节点管理接口文档（集群平台 / 云平台管理端）

> 适用模块：`Admin` 管理端（Django）
> 服务端口：`config.json` 中 `adminPort`（当前为 `9824`）
> 服务地址示例：`http://192.168.88.203:9824`
> 源码入口：`Admin/app/urls.py` 中「节点管理」路由段 → `Admin/app/views/NodeView.py`
>
> 说明：本文档描述**管理端（集群平台 / 云平台侧）**对边缘节点的管理接口，与《集群管理平台对接接口.md》（设备端 `open/*` 接口）互补。管理端通过这些接口对已接入的边缘节点进行增删改查、在线同步与升级包下发。

---

## 1. 概述

管理端维护一张 `eai_node` 节点表，用于登记接入集群平台的边缘计算节点（AI 边缘计算服务）。节点管理模块提供以下能力：

- 节点列表查询（分页，Web 页面）
- 节点新增 / 编辑 / 删除
- 节点在线状态同步（调用设备端 `/open/discover` 及数据同步接口）
- 节点升级包下发（调用设备端 `/system/openImportUpdate2`）
- 节点详情 / 数量统计

### 1.1 节点管理路由

| 前缀 | 说明 |
| --- | --- |
| `node/index`、`node/add`、`node/edit` | Web 页面接口，需登录会话 |
| `node/open*` | 开放 JSON 接口（`openDel`、`openSync`、`openImportUpdate`、`openNodeDetail`） |

### 1.2 鉴权方式

管理端中间件（`Admin/app/middleware.py` 的 `SimpleMiddleware`）规则：

- 已登录会话（`session["user"]` 存在）直接放行；
- 未登录时，以下前缀路由**放行**（无需登录即可访问）：

  ```
  login / captcha
  open/
  node/open
  alarm/open
  media/open
  stream/open
  control/open
  storage/
  inner/
  ```

- 其余路由（含 `node/index`、`node/add`、`node/edit`）重定向到 `/login`。

> ⚠️ 注意：`node/open*` 接口在中间件层**免登录放行**，且当前实现未做额外的 `Safe`/`Eai-Secret` 校验。若部署在公网，建议在反向代理层对 `node/open*` 增加访问控制。

### 1.3 通用响应格式

- **页面接口**（`index` / `add` / `edit`）：默认渲染 HTML 页面；当请求头携带 `X-Requested-With: XMLHttpRequest` 时返回 JSON。
- **开放接口**（`node/open*`）：统一返回 JSON（`Content-Type: application/json; charset=utf-8`）。

**业务码约定：**

| code | 含义 |
| --- | --- |
| `1000` | 成功 |
| `0` | 失败（具体原因见 `msg`） |

通用结构：

```json
{ "code": 1000, "msg": "success" }
```

## 3. 节点数据模型（`eai_node` 表）

### 3.1 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | int | 自增主键 |
| `user_id` | int | 创建用户 ID（取自登录会话） |
| `sort` | int | 排序号 |
| `code` | varchar(50) | 节点编号（唯一；为空时自动生成 `node` 前缀随机码） |
| `nickname` | varchar(100) | 节点昵称 |
| `version` | float | 节点软件版本（同步时更新，来源 `project_version`） |
| `flag` | varchar(50) | 项目标记（同步更新，来源 `project_flag`） |
| `system_name` | varchar(100) | 系统名称（同步更新） |
| `machine_node` | varchar(100) | 机器节点 / 架构（同步更新，如 `arm64`） |
| `address` | varchar(200) | 节点地址，如 `http://192.168.1.100:9001`（需带协议前缀） |
| `eai_safe` | varchar(100) | 集群密钥，用于设备端 `Eai-Secret` 校验 |
| `media_secret` | varchar(100) | 媒体服务密钥 |
| `machine_mac` | varchar(50) | 设备 MAC（同步授权信息） |
| `is_auth` | int | 是否已授权（`0/1`） |
| `is_multi_process` | int | 是否多进程（`0/1`） |
| `max_count` | int | 最大路数 |
| `desc` | varchar(200) | 授权描述 |
| `auth_info` | text | 授权信息 JSON（同步更新） |
| `state` | int | 节点状态（见 3.2） |
| `image_path` | varchar(200) | 图片路径 |
| `expand1` / `expand2` | varchar(200) | 扩展字段 |
| `create_time` | datetime | 创建时间 |
| `last_update_time` | datetime | 最后更新时间 |
| `node_code` | varchar(100) | 设备端返回的设备编号（同步更新） |
| `node_host` | varchar(100) | 设备端 Admin 服务地址（同步更新） |

### 3.2 节点状态 `state`

| 值 | 含义 |
| --- | --- |
| `0` | 未同步 |
| `1` | 在线 |
| `2` | 掉线 |
| `3` | 版本不支持 |
| `4` | 读取节点信息失败 |

## 4. 各接口详解

### 4.1 节点列表

**接口：** `GET /node/index`

**用途：** 分页查询节点列表，渲染节点管理页面。

**请求参数（Query）：**

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `p` | int | 否 | `1` | 页码（从 1 开始） |
| `ps` | int | 否 | `10` | 每页条数（`<1` 时按 `1` 处理） |

**响应：** HTML 页面（`templates/app/node/index.html`）。页面上下文含：

- `data`：节点列表（`eai_node` 行，含 3.1 全部字段）
- `pageData`：分页信息

`pageData` 结构：

```json
{
  "page": 1,
  "page_size": 10,
  "page_num": 1,
  "count": 12,
  "pageLabels": ["1", "2"]
}
```

---

### 4.2 新增节点

**接口：** `GET /node/add`（打开新增页面） / `POST /node/add`（提交新增）

**用途：** 登记一个新的边缘节点。

**GET 响应：** 渲染新增页（`templates/app/node/index.html` 新增表单），`handle=add`，并预生成一个随机 `code`（`node` 前缀）。

**POST 请求参数（表单 / form-data）：**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `handle` | string | 是 | 必须为 `add` |
| `sort` | int | 否 | 排序号，默认 `0` |
| `code` | string | 否 | 节点编号；为空自动生成 `node` 前缀随机码 |
| `nickname` | string | 是 | 节点昵称，不能为空 |
| `address` | string | 是 | 节点地址，不能为空（建议带 `http://` 前缀） |
| `eai_safe` | string | 是 | 集群密钥，不能为空 |
| `media_secret` | string | 是 | 媒体密钥，不能为空 |

**校验规则：**

- `handle` 必须为 `add`；
- `nickname` / `address` / `eai_safe` / `media_secret` 非空；
- `code` 在 `eai_node` 表中不得重复（重复报 `the data already exists`）。

新增成功默认 `state=0`（未同步），可通过 `/node/openSync` 触发同步。

**响应：**

- AJAX（请求头 `X-Requested-With: XMLHttpRequest`）：

```json
{ "code": 1000, "msg": "添加成功" }
```

- 普通请求：渲染 `message.html`（成功跳转 `/node/index`，失败回 `/node/add`）。

---

### 4.3 编辑节点

**接口：** `GET /node/edit?code=<code>`（打开编辑页） / `POST /node/edit`（提交编辑）

**用途：** 修改节点信息。

**GET 参数（Query）：**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | string | 是 | 节点编号；不存在时提示「该节点不存在」并跳回列表 |

**POST 请求参数（表单 / form-data）：**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `handle` | string | 是 | 必须为 `edit` |
| `sort` | int | 否 | 排序号 |
| `code` | string | 是 | 要编辑的节点编号 |
| `nickname` | string | 是 | 节点昵称 |
| `address` | string | 是 | 节点地址 |
| `eai_safe` | string | 是 | 集群密钥 |
| `media_secret` | string | 是 | 媒体密钥 |

**校验规则：** 同新增；节点不存在时报 `the data does not exist`。

**响应：**

- AJAX：`{ "code": 1000, "msg": "编辑成功" }`
- 普通请求：成功跳转 `/node/index`，失败回 `/node/edit?code=<code>`。

### 4.4 删除节点

**接口：** `POST /node/openDel`

**用途：** 删除指定节点记录。

**请求参数（Body，表单 / form-data 或 JSON）：**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | string | 是 | 节点编号 |

**响应示例：**

```json
{ "code": 1000, "msg": "success" }
```

常见失败：

```json
{ "code": 0, "msg": "the data does not exist" }
{ "code": 0, "msg": "code is required" }
{ "code": 0, "msg": "request method not supported" }
```

---

### 4.5 同步节点

**接口：** `POST /node/openSync`

**用途：** 遍历所有节点，逐个调用设备端接口同步节点信息、视频流、算法流（详见第 5 章）。

**请求参数：** 无。

**响应示例：**

```json
{ "code": 1000, "msg": "成功2条，失败1条" }
```

> 同步操作耗时与节点数量相关，建议异步 / 低频触发。

---

### 4.6 导入并下发升级包

**接口：** `POST /node/openImportUpdate`

**用途：** 上传升级包（multipart/form-data），先存到管理端临时目录，再通过设备端 `/system/openImportUpdate2` 接口下发到指定节点。

**请求参数（Body，`multipart/form-data`）：**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `node_code` | string | 是 | 目标节点编号 |
| `file` | file | 是 | 升级包文件 |

**处理流程：**

1. 校验节点存在且状态合法（`f_checkNode`：`state=1` 才允许下发，未同步/离线会失败）；
2. 将 `file` 上传至管理端临时目录（`config.json` 的 `uploadTempDir`）；
3. 拼装下载地址：`http://<externalHost>:<adminPort>/static/upload/temp/<filename>`；
4. 以请求头 `Safe: <node.eai_safe>` 调用设备端 `POST {address}/system/openImportUpdate2`，Body 为 `{"url": "<download_url>"}`，超时 300s；
5. 下发成功后删除临时文件；若下发过程中节点重启导致异常，等待 10s 后自动触发 `f_syncNode(code)` 重新同步，并提示「更新完成」。

**响应示例：**

```json
{ "code": 1000, "msg": "success" }
```

常见失败：

```json
{ "code": 0, "msg": "file is required" }
{ "code": 0, "msg": "节点未同步" }
{ "code": 0, "msg": "节点离线" }
{ "code": 0, "msg": "节点不存在" }
```

## 5. 节点同步流程（`f_syncNode`）

`/node/openSync` 与升级包下发后的自动同步均调用 `ViewsBase.f_syncNode()`，对每个节点执行以下流程：

```mermaid
flowchart TD
    A[遍历节点列表] --> B[GET {address}/open/discover?is_auth=1<br/>请求头 Eai-Secret: node.eai_safe]
    B --> C{节点在线且返回 code=1000?}
    C -- 否 --> D[state=2 掉线<br/>或 state=3 版本不支持]
    C -- 是 --> E[更新节点信息<br/>version/flag/system_name/machine_node<br/>node_code/node_host/授权信息]
    E --> F[GET {address}/open/getAllStreamData<br/>同步视频流到 eai_node_stream]
    F --> G[GET {address}/open/getAllAlgroithmFlowData<br/>同步算法流到 eai_node_algorithm_flow]
    G --> H[state=1 在线]
    D --> I[记录 last_update_time 并保存]
    H --> I
    I --> J{还有下一个节点?}
    J -- 是 --> A
    J -- 否 --> K[返回 成功N条，失败M条]
```

要点：

- 请求头：管理端用 `Eai-Secret: node.eai_safe`（数据库中 `eai_node.eai_safe` 字段）调用设备端 `/open/discover`；同步视频流 / 算法流时请求头为 `Safe: node.eai_safe`。
- 若设备端 `clusterSecret` 校验失败，会返回 `{"code":0,"msg":"Eai-Secret 校验失败"}`，导致该节点同步失败（`state=2`）。此时需核对管理端 `eai_node.eai_safe` 与设备端 `clusterSecret` 是否一致。
- 视频流 / 算法流按 `stream_code` / `flow_code` 去重合并，`node_codes` 字段以逗号分隔记录归属的多个节点。
- 节点 `address` 必须带 `http://` 前缀，否则请求会因 `MissingSchema` 失败。

### 6.4 常见问题排查

| 现象 | 可能原因 |
| --- | --- |
| 同步后节点一直离线（`state=2`） | 设备端 `clusterSecret` 与 `eai_node.eai_safe` 不一致；或节点 `address` 缺 `http://` 前缀 |
| 返回 `Eai-Secret 校验失败` | 见上；可 `curl -H "Eai-Secret: <key>" "http://<设备IP>:<port>/open/discover?is_auth=1"` 直接验证 |
| `node/open*` 免登录可访问存在安全隐患 | 当前实现未做额外校验，建议反向代理层加访问控制 |
| `openInfo` 调用 404 | 该函数未在 `urls.py` 注册，需手动添加路由 |
