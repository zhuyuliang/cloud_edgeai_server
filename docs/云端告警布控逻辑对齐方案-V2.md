# 云端与边缘侧业务逻辑对齐实施方案（V2 优化版）

> 本文档替代原《云端告警布控逻辑对齐方案.md》。
> 原则：**以边缘侧（edge_ai_video_analyzer/Admin，最新代码）为唯一事实来源**；云端（admin/）向其对齐；不发明两边都不存在的接口。
> 已确认的关键决策见附录 A。

---

## 0. 总体架构

```
┌────────────┐   Eai-Secret 鉴权（HTTP 转发/iframe 嵌入）  ┌────────────┐
│  云端 Admin │ ────────────────────────────────────────▶ │  边缘 Admin │
│  (Django)  │                                            │  (Django)  │
│            │ ◀──────────── 告警/统计主动推送 ──────────── │            │
└────────────┘   X-Push-Signature 签名（全局 push_secret）  └────────────┘
```

- **下行链路**（云端 → 边缘）：云端页面/接口 → 边缘 `open` 系集群接口，`Eai-Secret` 头鉴权（边缘 `SimpleMiddleware` 统一校验，密钥 = 边缘 `config.json` 的 `clusterSecret`，即节点 `eai_safe`）。
- **上行链路**（边缘 → 云端）：边缘 `push_alarm_to_cloud` → 云端新增 `alarm/openPush`；文件先上传到云端 `alarm/openUploadFile` 换 URL；签名头 `X-Push-Signature` / `X-Push-Timestamp`（HMAC-SHA256，密钥 = 全局 `push_secret`，云端存 `config.json`，边缘存 `CloudServiceConfig.push_secret`）。
- **页面模式**：布控与媒体源的新增/编辑均采用"双跳 iframe"——云端页面 iframe 嵌入边缘页面，提交直达边缘（见模块 1、2）。
- **老节点**：完全放弃。`alarm/openAdd`（base64 链路）、老 stream/控制兼容逻辑全部删除；节点版本不满足最低版本时 `eai_node.state=3`（版本不支持），页面屏蔽操作入口。

### 1.2 云端侧改动（`admin/`）

**模型与库表**（`eai_node_stream` 重构 + 新增媒体源明细表）：

```sql

  `source_type` smallint NOT NULL,             -- 1 RTSP / 2 RTMP / 3 FILE / 4 ONVIF / 5 GB28181

```

- 同步策略：节点上线/定时同步时调用边缘 `open/getAllStreamData` 全量刷新 `eai_node_media_source`（按 `(node_code, source_code)` upsert，云端有而边缘无的删除）。
- **页面**：
  - 列表页 `stream/index` 重写：按节点 + 源类型 Tab 展示，数据来自 `eai_node_media_source`。
  - 新增/编辑：iframe 嵌入边缘 `stream/openSource/addContext|editContext`（URL 携带 `Eai-Secret` 改用一次性票据或云端后端代理转发，见 §4.3）。
  - 删除/转发启停/PTZ：云端后端接口转发到边缘对应 openSource 接口。
- **点播链路**：保留 `inner/on_stream_not_found` → 边缘 `stream/openAddStreamPusherProxy`；按源类型分流策略（FILE 类源直接读边缘文件 URL，GB28181 走边缘 ZLM 拉流代理）。云端 ZLM 播放地址规则不变（`app={node_code}`，`name="{app}-{name}"`）。
- **清理**：删除云端老 `stream/add|edit|postDel` 等本地媒体源 CRUD 页面与老协议的代理转发代码（问题 3 决策 A）。

### 1.3 验收标准

- 云端可查看任一节点 5 类媒体源清单，状态与边缘一致（同步延迟 ≤ 同步周期）。
- 云端可对任一节点完成 新增/编辑/删除/转发启停 媒体源，操作结果与边缘一致。
- 节点离线时云端页面给出明确提示，不报错。
- 云端点击播放在边缘未推流时能触发级联拉流并成功播放。

## 3. 模块三：报警管理

### 3.1 上行链路重做（核心）

**云端新增接口**（均需加入 `middleware.py` 免登录白名单 `alarm/open` 前缀——已覆盖）：

**① `POST alarm/openUploadFile`** —— 边缘告警媒体文件上传
- 验签：`X-Push-Signature` / `X-Push-Timestamp`（HMAC-SHA256，全局 `push_secret`，时间戳容差 ±5 分钟；`push_secret` 为空时按边缘 `PushSigner.verify_sign` 语义跳过验证，但生产环境强制配置）。
- 接收 multipart 文件 → 存储到 `storage/alarm_upload/{yyyyMMdd}/` → 返回 `{"code":1000,"data":{"url":"<可访问URL>"}}`。
- URL 由云端静态服务/专用 media 路由提供访问。

**② `POST alarm/openPush`** —— 告警推送接收（JSON，格式以边缘 `push_alarm_to_cloud` 为准）

```json
{
  "msg_type": "alarm",
  "event_id": "ALARM_20260916123045_123",
  "event_type": "carplate_task",
  "event_time": "2026-09-16 12:30:45",
  "risk_level": 1,
  "control_code": "...",
  "task_name": "...",
  "description": "...",
  "image_url": "...", "video_url": "...",
  "detect_objects": [...],
  "device_info": {"device_id": "...", "device_name": "...", "device_ip": "..."}
}
```

处理逻辑：
1. 验签（同 ①）。
2. 幂等：`eai_node_alarm.event_id` 唯一索引，重复推送直接返回 1000。
3. 节点路由：`device_info.device_id` → `eai_node.code`；找不到节点返回明确错误码（便于边缘日志排查），不静默丢弃。
4. 状态映射：边缘侧**仅推送非复检态告警**（state ∈ {0,1,2,3}），云端直接落库该状态；若边缘推送 4/5/6 复检态，云端按 1（未处理）兜底。
5. 落库字段映射（新字段见 3.2）：`risk_level→risk_level`、`detect_objects→detect_objs`、`task_name→task_name`、`event_id→event_id`、`description→desc`、`image_url/video_url→image_path/video_path`（存 URL）。
6. 返回 `{"code":1000,"msg":"success"}`；边缘按现状重试（3 次）。

**msg_type 扩展**：`msg_type="statistic"` 接收统计/计数告警推送（边缘需新增 `push_statistic_to_cloud`，字段含 control_code / count / enter_num / leave_num / total_num / reset 信息），落库 `eai_node_statistic_alarm`；`msg_type="statistic_reset"` 接收边缘自动周期清零通知，云端同步清零对应记录。

### 3.2 云端模型与迁移

`eai_node_alarm` 新增字段：

```sql
ALTER TABLE `eai_node_alarm`
  ADD COLUMN `event_id` varchar(64) NOT NULL DEFAULT '' AFTER `code`,
  ADD COLUMN `risk_level` smallint NOT NULL DEFAULT 0 AFTER `level`,

  ADD COLUMN `detect_objs` text NULL,

```

新建统计表：

```sql
CREATE TABLE `eai_node_statistic_alarm` (
  `id` int NOT NULL AUTO_INCREMENT,
```

**存量状态迁移（必须降序执行，避免连锁覆盖）**：

```sql
-- 旧语义: 0未处理 1已处理 2误报 5删除  →  新语义: 0未读 1未处理 2已处理 3误报
UPDATE `eai_node_alarm` SET `state`=3 WHERE `state`=2;   -- 误报 2→3
UPDATE `eai_node_alarm` SET `state`=2 WHERE `state`=1;   -- 已处理 1→2
UPDATE `eai_node_alarm` SET `state`=1 WHERE `state`=0;   -- 未处理 0→1
-- state=5（逻辑删除）保持 5 不变，列表查询排除
```

- 同步更新 `docker/database.sql`（新部署）与提供升级 SQL 脚本（存量库），两条路径都要验证。
- `NodeAlarmModel` / 新增 `NodeStatisticAlarmModel` 同步更新。

### 3.3 云端页面与接口

- **页面拆分**（镜像边缘 `alarms/*` 分类，路由用云端自有风格）：
  - `alarm/event`：事件告警（`alarm_category=0`，task_name 不属于车牌/人脸/计数类）
  - `alarm/carplate`：车牌告警（复用 `main_plate_*` 字段展示）
  - `alarm/face`：人脸告警（复用 `main_track_max_*` 字段展示）
  - `alarm/count`：计数告警 + 周期统计（数据来自 `eai_node_statistic_alarm` 及计数类告警）
  - `alarm/history`：历史查询（全量、多条件筛选、导出）
- **处理动作**：`alarm/openHandle` 保留"已处理/误报"两动作，**仅本地改库不回传节点**；填写处理信息写 `deal_info`。
- **手动清零（唯一回传例外）**：计数页提供"清零"按钮 → 云端后端转发到边缘新增 `alarms/openResetCount`（Eai-Secret 鉴权，复用边缘 `api/resetCountAlarm` 逻辑）→ 边缘清零成功返回 → 云端同步清零 `eai_node_statistic_alarm` 对应记录；边缘失败则云端不改动并提示。
- **导出**：`alarm/openExport` 适配新字段与分类筛选。
- **清理**：删除 `alarm/openAdd`（base64 链路）及老节点上报相关代码。

### 3.4 边缘侧改动

- 新增 `alarms/openResetCount`（POST，复用 `api/resetCountAlarm`）。
- `push_alarm_to_cloud` 小改：
  - `alert_data` 中补充 `alarm_category`（0/1/2/3，按 task_name 归类逻辑与边缘页面一致）与 `state`；
  - **跳过复检态**（state ∈ {4,5,6}）不推送；
  - 新增 `push_statistic_to_cloud`（计数告警/周期清零推送，`msg_type=statistic / statistic_reset`）。
- 配置项：边缘 `CloudServiceConfig.alert_push_url` 指向云端 `alarm/openPush`，`alert_upload_url` 指向云端 `alarm/openUploadFile`，`push_secret` 与云端全局配置一致。云端节点管理页提供"推送配置检查"提示（可选增强）。

### 3.5 验收标准

- 边缘触发各类告警后 ≤ 推送超时时间内云端对应分类页可见，图片/视频可访问。
- 同一告警重复推送不产生重复记录（event_id 幂等）。
- 云端标记已处理/误报仅影响云端；边缘状态不变。
- 云端清零后边缘与云端统计值同时归零；边缘自动周期清零后云端随之更新。
- 存量告警迁移后状态显示正确（抽样比对迁移前后数量一致）。

## 4. 公共改造项

### 4.1 云端中间件白名单（`admin/app/middleware.py`）

- `alarm/openPush`、`alarm/openUploadFile` 已在 `alarm/open` 前缀白名单内，无需新增；
- 新增 `alarm/event|carplate|face|count|history` 为登录态页面，无需白名单；
- 复核所有新增 open 接口均落在既有放行前缀内（`control/open`、`stream/open`、`alarm/open`）。

### 4.2 老代码删除清单（问题 3 决策 A）

云端：
- `AlarmView.api_openAdd`（base64 链路）及 `alarm/openAdd` 路由；
- 老 stream 本地 CRUD（`stream/add|edit|postDel*` 等）及对应模板；
- `ControlView` / `StreamView` 中 `version < 2` 兼容分支；
- `api_openHandleAllStreamProxy` 指向边缘缺失接口的调用（边缘补齐后恢复）。

边缘：无需删除，仅新增。

### 4.3 iframe 嵌入鉴权方案

边缘 open 页面（Context 接口）依赖 `Eai-Secret` 头，浏览器 iframe 无法自定义请求头。方案：
- 云端后端增加代理路由（如 `proxy/node/<node_code>/<path>`），登录态校验后由后端附加 `Eai-Secret` 转发到边缘，页面/接口响应原样回传（含静态资源路径重写，限定白名单路径：`control/open*`、`stream/openSource/*Context`）。
- 边缘侧模板渲染时的静态资源、AJAX 地址使用相对路径，保证经代理可用。

### 4.4 配置项汇总

| 配置 | 位置 | 说明 |
|---|---|---|
| `push_secret` | 云端 `config.json`（全局一个） | 推送验签密钥 |
| `push_secret` | 边缘 `CloudServiceConfig.push_secret` | 与云端一致 |
| `alert_push_url` | 边缘 `CloudServiceConfig` | `http(s)://<云端>/alarm/openPush` |

| `clusterSecret` | 边缘 `config.json` | = 云端节点记录 `eai_safe` |
